# 角色分工：拆解端 / 执行端 / 质检端

一套多智能体协作，真正难的不是"让 AI 干活"，而是让三个部分各自知道边界在哪。

## 三个角色

| 角色 | 在哪运行 | 职责 | 不做什么 |
|---|---|---|---|
| **拆解端（总经理）** | 云端 | 听懂人话、拆成可执行任务卡、排优先级、决定什么时候必须停下问人 | 不直接操作电脑、不做破坏性动作 |
| **执行端** | 本机 | 按任务卡逐步操作、截图取证、如实回报 | 不自行扩大范围、不替人做决定 |
| **质检端** | 云端或本机 | 验收回执、指出证据缺失、判定是否返工 | 不重做执行端的活，只判定 |

## 交接契约

1. **拆解端**产出任务卡：目标一句话、允许的操作、禁止的操作、步骤、完成标准、停止条件、需要回传什么证据。
2. **执行端**认领并执行：先改状态再动手；遇到范围内没写的情况立即停，回执写"需确认"。
3. **质检端**验收：证据齐不齐、有没有越界、结论和数据对不对。不合格就开返工卡，而不是让执行端自己说"我完成了"。

## 三条最有用的实践经验

**第一，任务卡写太虚，执行端一定会自由发挥。**
"优化一下页面"不是任务卡；"把首屏加载时间从 X 降到 Y，允许改这三个文件，禁止改依赖"才是。

**第二，回执必须能被别人复核。**
只写"已完成"的回执等于没有回执。要写清楚改了什么、在哪看、怎么验证。

**第三，让"停止"成为一等公民。**
大多数自动化出问题，不是因为能力不够，而是因为越界时没有停。所以每个任务卡都要有停止条件，而且停止不该被视为失败。

## 常见失败模式

| 症状 | 真实原因 | 处理 |
|---|---|---|
| 同一件事被做两遍 | 认领和改状态不是原子操作 | 先改状态再动手 |
| 报告说做完了但没做 | 缺证据要求 | 无证据视为未完成 |
| 越改越乱 | 任务卡没有"禁止的操作" | 白名单约束 |
| 卡在同一个错上反复重试 | 把"需确认"当成"失败" | 区分失败语义 |
| 上下文丢失后行为突变 | 规则只写在提示词里 | 规则写进任务卡 |
